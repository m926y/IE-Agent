# S1 账号与个人信息改造

基线：主仓库 `fe600cc`；本次改造日期：2026-10-28。

## 已完成

- 安全员创建司机/安全员账号后，一次性显示可复制的初始登录信息，不写浏览器持久存储或审计正文。
- 新账号首次登录只能进入改密流程，后端同步阻止业务接口；改密后旧密码及全部旧本地会话失效。
- 创建司机后可直接进入身份核实页，预填目标账号；司机选择器加载完整分页数据。
- 两类角色均有个人信息页：用户名、姓名/昵称、头像上传/样式、更改密码。修改用户名需验证当前工作台密码（可信 SSO 会话可修改其映射的应用用户名）。
- 头像在浏览器裁剪压缩，后端限制格式/大小，拒绝 SVG 和远程图片地址；头像随账号持久保存。
- 车辆展示名由数据库 `vehicle_labels` 固定映射为“车辆1”等；页面列表、详情、绑定、回放、根因、AI 文本使用展示名。原始外键用于查询与关联，未改写算法数据；这是展示层改名，不代表删除或加密原始字段。
- 查询框支持“车辆1”；AI 工具也能解析展示编号，解析后仍执行原工具权限校验。
- 简化登录页、账号管理和常用操作中的技术说明，保留权限、数据覆盖、低可信度及错误提示。

## 接入现有数据库

先备份并检查数据库是否存在仅大小写不同的用户名，然后按顺序执行：

1. `scripts/contract/migrations/008_account_profile.up.sql`
2. `scripts/contract/migrations/009_vehicle_labels.up.sql`

008 为 `app_users` 增加头像、首次改密标志和用户名唯一约束，存量账号不强制改密。009 初始化持久化车辆展示编号，并在新增/更新司机车辆关系时补齐新车辆的展示编号。新表只通过服务端接口按角色返回授权映射；按部署环境现有数据库角色调整 GRANT。

运行 `npm ci`、`npm run typecheck`、`npm run build`，在原有服务器环境启动 `npm start`。沿用 HOST、PORT、数据库及模型环境变量，无需把真实密钥写入源码。

**本次未连接/迁移线上数据库，也未发布线上应用。** 迁移是上线前置步骤；本地测试库不代替生产 PostgreSQL 验收。

## 验收路径

安全员登录 → 系统管理创建账号 → 安全交付初始凭据 → 新账号登录 → 强制修改初始密码 → 新密码重新登录 → 安全员核实司机绑定 → 司机读取本人业务数据。

司机底部“个人信息”、安全员顶部“个人信息”：修改昵称/头像后保存，顶部身份同步；用户名重名拒绝；更换密码后要求重新登录。千问平台的 SSO 密码需在千问账号设置中修改，此页维护的是映射的工作台账号密码，不能声称修改了外部身份提供方密码。

运行 `npm run test:accounts`。12 项检查覆盖完整账号链路、两种角色、首次改密门禁、旧密码与旧会话失效、用户名唯一性、头像持久化、字段越权防护、车辆映射范围、司机绑定及凭据不进入审计。本测试只用本地端口；受限环境需允许本机网络访问。

页面验证已确认两端个人信息入口、头像预设和昵称保存及顶栏同步。自定义图片上传的文件选择器自动化发生超时，尚未完成浏览器上传至保存的全程验收；后端图片保存与不支持格式拒绝已通过测试。
