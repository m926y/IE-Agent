## 一、这个项目是干什么的（一句话）

把我们初赛的两套算法——**任务一：未来 40 天事故风险预测**、**任务二：近 14 天安全评分/六维扣分/可信度/事件证据**——变成一个**真正能用的安全管理产品**：安全员在电脑上发现风险、核实证据、找人谈话、安排培训；司机在手机上每天收到一份 AI 写给自己的一日安全简报，能看分数、看证据、提异议、做学习。全链路"预测 → 解释 → 干预 → 培训 → 反馈 → 复评"在线闭环跑通。

**两层登录**：先用千问办公/DingTalk 平台账号进门，再用应用账号进入角色：

| 角色 | 登录名 | 密码 | 界面 |
|---|---|---|---|
| 安全管理员（配置+处置一肩挑） | `safety_admin` | `xingan-admin` | 电脑宽屏工作台 |
| 演示司机（绑定 DEMO_D0149） | `driver_demo` | `xingan-driver` | 手机窄屏"我的安全"端 |

技术上：B/S 架构，部署为千问办公动态 Page（Node.js 服务端 + React 前端 + 平台托管的 Supabase 数据库），手机/电脑浏览器直接访问，无需安装。

## 二、司机端已实现的功能（重点）

司机的界面就 5 个底部标签，每一个都对应题面要求：

### 1. 今日安全简报（AI 每天自动生成、主动推送）★核心
- **服务端每天自动生成**，不用司机打开网页才计算：到点后由调度任务为每个"已核实绑定"的司机生成并推站内通知；没赶上的，司机打开时也会自动补生成，且重复触发不重复推送（同一天同一份数据只有一份结论）。
- 简报内容：一句**个性化问候**（"晚上好，评分 28.14 显著低于车队均值 74.4，车道保持亟待提升"这种）＋** personalized 分析**＋**个人评分 / 车队均分双卡对比**＋**近 7 个观测日趋势双折线图**（悬停可看每天的分值）＋**本期最值得关注的前 1-3 项风险**（每项带事件次数、时间跨度、证据编号）＋**今日改善目标**＋**"我已阅读今日建议"按钮**。
- 关键：**AI 只负责"写话"，数字全部来自冻结的算法事实**。我们用三重守门把大模型管住：①文中出现任何数字，必须能在输入事实里逐字找到（新数字、百分比一律拒发）；②每条建议必须引用真实证据 ID；③违禁措辞（"实时监测""刚刚发生""风险已改善"等）直接拦截。不过关自动重试修复一次，再不过就退回规则模板并如实标注——**宁可朴素，不发一句没依据的好话**。
- 昨天没开车？简报不会编造"今日表现"，会明说"无新驾驶记录"，继续跟踪上期目标。

### 2. 我的安全（看自己，也看团队但不暴露任何人）
- 本人最新安全分、等级、可信度、7 天变化、未来 40 天概率，每个数字带日期和口径；近 8 日评分历史与六维扣分条形图，每行都能**点开"查看依据"**钻取到对应的评分证据和台账分摊。
- **匿名车队统计**：只给人数、平均分、A-D 分布，永远看不到任何具体司机；样本太少或能反推到个人时自动隐藏——隐私是服务端强制的，不是前端藏一下。

### 3. 历史风险与沟通（接受安全员的干预）
- 安全员发来的干预消息在这里：能看到**发送时间、消息原文、关联案卷**，可"标记已读"（幂等，重复点不重复记）、可**回复**（司机的话进入培训复核材料，一字不改）。
- 页面明示这是历史回放与人工沟通记录，不是实时警报；"无记录"不等于"没风险"。

### 4. 培训任务（做学习、留记录、给反馈）
- 安全员分配的课程在这里完成：看目标与完成条件 → 开始 → 边学车边"保存草稿"→ 提交（提交后司机端不能再改）。
- **离开保护**：草稿没保存就切页，会弹窗提醒"先保存再走"，保存失败原地停留、输入不丢。
- 培训未通过人工复核前，系统不会说"已完成"；做完后系统跟踪"下一周期复评"，没有新数据就写"待下一周期"，**绝不宣称"培训让分数提高了"**。

### 5. 我的资料 + 消息 + 复核申请（EV05）
- 维护本人联系方式与备注（服务端只认这个人，改不动绑定和评分）；
- 对**自己真实存在**的评分/证据一键提交异议，可跟踪处理状态（核查中→待数据方→已答复→已关闭），答复原文留档；数据纠错走版本化重建，**不存在"司机端改分"这条路**。

**司机端红线一句话**：只读算法事实、只写自己的记录、只看自己的数据——权限在服务端每条 API 上执行，越权和"记录不存在"返回同一个 404，不泄漏任何存在性。

## 四、AI 能力怎么做的（创新点核心）

1. **15 个受控工具，而不是裸聊**。大模型只能通过我们写的工具读数据（评分/预测/台账/队列/案卷/任务/复核/知识/规则/根因聚合/干预草稿/培训草稿/动作预演……），身份由服务端会话决定，谁问、能答什么，模型自己说了不算。越权直接拒绝，且**不告诉它"存在但不给你看"**。
2. **技能路由**：问题自动分诊给 5 个专家角色（评分解释/车队分诊/干预沟通/培训/案卷跟进），每个技能带自己的口径纪律和工具预算。
3. **每条数字可点开验证**：回答里的关键数字生成"证据卡"（表/字段/record_id/截止日/来源版本/可信度），点"打开/重新验权"当场按你的会话再查一遍——**AI 说的每句话都能回源对账**。
4. **AI 永远不动库**：起草的沟通/培训文本一律是"草稿，未发送"，必须人类在对应页面点独立确认按钮才写入；发送后原始问答与人工采纳动作全程审计（SM04 里 ai.chat/ai.confirm 可查可导出）。另有"三种管理动作并排预演"和"历史回放时点问答"（只用当时已知信息，事后数据标明"事后参考"）。
5. **每日简报的人格化+守门人**（见司机端第 1 条）：这是"AI 创新性"最直接的展品——同一条管线，先算数、后写话、再验话。
6. 模型仅使用通义千问系列（千问办公内置通道 / 属主百炼 Token Plan 订阅，二者均为 Qwen；当前 qwen3.7-plus），未引入任何第三方模型与非授权数据服务。

## 五、按四个评分维度，我们的对标自评

- **功能完整性（30%）**：五大模块逐条覆盖（见对照表），"登录→评价→报警→干预→培训→反馈→复评"全链在一个在线多人环境跑通，且双角色同库实时互通（管理员建任务，司机端切页即见）。
- **业务实用性（30%）**：所有流程贴着车队真实动作设计——安全员一天从"今天先处理谁"开始（RM01/AI04），谈话前先看证据四标签，发不发消息有"案卷关闭"状态机拦着；司机端像"安全版钉钉日报"，看分、看证据、申辩、学习、反馈一条龙；异议处理、设备核验优先、"低可信不惩罚"这些都写成了系统约束而不是口号。
- **AI 创新性（30%)**：受控工具+证据卡回源+技能路由+草稿-人工确认双保险+每日简报"算数与写话分离"的守门架构；另有 AI 辅助培训摘要（引用逐条可验，缺证自动说"无法判断"）与一句话三路径预演。
- **交互体验（10%）**：驾驶安全主题"行安"视觉体系，浅色工作台+司机移动优先卡片流；每个空态区分"没数据/没权限/没覆盖/加载失败"，从不拿 0 冒充空；红/琥珀色只用于真正的风险与待核验；停车后才阅读的提示语等细节。

## 六、我们特意"没做"的事（诚实红线，答辩可直接引用）

1. **不造假实时流**：演示数据快照截至 2026-07-31（评分历史 7-24~7-31，883 条回放事件），页面凡涉"当天/实时"均明确标注"历史回放口径，无记录≠零风险"；接入新日期 CSV 后趋势/简报自动延伸，无需改代码。
2. **不造分数**：算法值只读，异议走"核查-答复-版本化重建"，没有任何页面/接口/AI 能改一行评分。
3. **AI 不自动动作**：不自动发送、不自动分配、不自动判培训效果；"我已阅读"永远不等于"行为已改善"。
4. **模型不外联**：无第三方大模型、无外部专业数据服务。

## 七、现场演示建议脚本（15 分钟）

1. 登录管理员 → 数据总览（500 车/6 维/真实截止日）→ EV06 根因（"为什么是这批车"）。
2. RM01 点"7 天滑降"→ 打开某车 EV03 四标签 → 证据台账 → RM03"证据属实"→ AI 侧栏起草干预 →「填入草稿」→ **人工确认发送**。
3. 手机/窄屏切 driver_demo → 安全简报 tab：AI 个性化简报（趋势图+悬停读数+证据钻取）→ 我的消息收到干预 → 回复。
4. TR02 分配已审课程（按映射自动强制）→ 司机端做课（演示离开保护）→ 提交 → TR06 四栏复核：AI 摘要（点引用回源）→ 人工"通过"→ TR03 复评显示"待下一周期数据"。
5. SM05 现场改一维权重：草案→批准→生效→AI 问答引用新口径版本；SM04 审计台导出 CSV（含 ai.chat 记录）。
6. 收尾：司机提交一条异议 → 管理员答复 → 司机端可见答复（呼应"公平可申诉"）。
