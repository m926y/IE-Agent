## 技术验收方法

冻结代码后执行类型检查、默认测试、来源浏览器验收、候选清单生成和来源案例对照。浏览器流程覆盖司机与安全员阅读保存、刷新、提交、退回补充、复核、证据关联、未保存保护、并发冲突、服务失败、身份变化及会话过期。预期401/403/404/409/503与非预期故障分开记录。

对照采集从实际来源按low、medium、high可信度分层选取案例，每组至多6例，总计12—20例；不足时明确失败而不是补造。每例重复3次，轮换A/B/C的采集顺序，保持同一来源版本及本人权限。

| 入口 | 实际采集 | 解释边界 |
| --- | --- | --- |
| A 现有分散页面 | 本人评分、历史、任务、沟通、复核、风险记录 | 当前现有入口，不回退历史代码 |
| B 来源证据核对 | 本人评分、对应证据与历史 | 直接核对来源，不生成专业建议 |
| C 行动与质量分流 | 本人行动摘要、证据与两期评分 | 确定性分流，不冒充AI模型调用 |

关键字段检查为score_id、安全分、截止日、来源版本逐字段对照真实来源。另验证低可信提示、其他司机证据拒绝及未核实身份不能新增复核申请。该检查不等于评审者对建议或解释的人工判断。响应时间只记录本机接口采集p50/p95，入口负载不同，不将其解释为司机操作时间或认知改善。

## 人工评审后补步骤

运行 `npm.cmd run test:value` 后，从技术对照结果中的evidence_directory找到隔离材料：cases.json为真实案例和入口返回；interface-runs.json为逐次接口耗时；human-ratings.json为留空评分表。材料不含口令或会话令牌，业务明细只留在忽略提交的.source-tests目录。

1. 安排两名实际评审者，记录真实身份或匿名编号及日期。评审前由维护者在独立测试工作台将技术司机映射到案例来源司机；不得借用用户运行库或把技术映射当作真实身份核验。
2. 按每例presentation_order查看A/B/C材料；两位评审独立完成同一问题，先不互看评分。表中的reviewer_slot只是空位，不表示已经有人参加。
3. 实际填写开始/完成时间、是否完成任务、事实准确性、下一步是否适当、是否理解限制及意见。可以查看来源引用复核；未完成或无法判断时如实记录，不能默认满分。
4. 收回真实记录后比较任务完成率、查找时间和限制理解情况，报告样本量、顺序和局限。没有人工填写时，这些指标保持null和pending，不写提升百分比。

有限测试目标为关键字段可追溯、跨司机返回零条、未授权业务写入零条、缺失值不当作零风险。它们只适用于所执行的案例和负向检查，不是任意输入保证。这些案例初始无培训任务，完整培训与干预流程另由浏览器脚本验证；不把无任务案例伪装成培训效果研究。

## 诚实演示路径

先展示历史评分、来源截止日和原始证据，再展示无告警及课程未审核状态。正式运行库没有真实审批时停在待审核；隔离技术演示可明确标注临时审批，走分配、学习、保存、提交、退回、重提及复核。最后展示没有新评分时等待复评，不显示虚构分值或改善结论。

当前来源历史只有2026-07-24至2026-07-31八个滚动截止日，不提供四周趋势、实时风险或培训之后的效果证明。自动化验收不能替代课程内容审核。
