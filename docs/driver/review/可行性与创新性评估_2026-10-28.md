## 评估结论

原稿的缺口方向基本正确，适合保留“风险、干预、培训、复评”的主线；但代码已具有较多基础能力，不能再按从零建设排期。建议把开发收敛为“风险数据展示补齐、课程交付补齐、可信解释及复评条件校准”，复用既有鉴权、状态机与 AI 工具。

工程可行性：风险列表与课程阅读为高可行；测验、课程版本固化和跨对象追踪为有条件可行；当前没有实时数据接入与可比后续样本，真实实时监控和有效性证明尚不具备完成证据。按两名熟悉项目的开发者估算约 7—11 人日，并另留一个完整回归日；工期取决于数据和运行环境到位情况。

创新性：通用问答、工具调用、证据卡和培训流程本身不足以支持算法原创性主张。更有价值的项目内增量是“按证据与数据质量分流的个性化改善闭环”：低可信时先核验数据，证据充分时匹配已批准课程，完成后等待可比新数据再复评。该主张仍须消融对比与人工评审验证，目前只能称为业务机制与集成创新。

## 必须优先处理的约束

1. **赛事模型通道许可待核实。** 本地《Crazy Logi-AI 2.0决赛要求详案.pdf》第1页明确限定千问办公集成模型，不允许其他第三方大模型服务。AGENTS.md 第35—37轮记录外部 Token Plan 接入，源码也允许配置外部 HTTPS 端点。使用同品牌 Qwen 并不自动证明该通道获赛事许可。正式演示前取得明确答复；未确认时按赛题许可通道部署并重验，不能在文档里宣称当前已符合要求。此项为已观察到的约束冲突，非推定违规结论。
2. **任务详情鉴权疑点。** handleTaskView 只 requireUser 后把 user.driver_id 传给 loadTask；loadTask 仅在 ID 为真值时追加过滤。未绑定司机的空 ID 可能绕过对象行过滤，待核实身份也没有此路径的显式检查。应在详情路由入口统一校验已核实绑定和对象归属，并覆盖其他角色；本次未用真库复现，按代码级高优先风险记录。
3. **并发状态流转。** start/submit/review 虽带旧状态条件 PATCH，但 return=minimal 且未验证受影响行数；draft 保存不带旧状态条件。需测试“提交与保存并发”“两位审核者并发”；不能仅因串行重复请求有 replay 就认定并发安全。
4. **空值和异常。** MyHistory/OwnScoreDetail 中 Number(null) 可变为0；RRRequestPanel 与 NotesInbox 的 catch 转空列表会掩盖故障。MyRisk 刷新失败保留旧列表但未标记陈旧；MyTraining blocked 分支未真正设置。应统一类型校验及错误映射。
5. **历史文档与契约漂移。** scripts/contract/app_tables.json 仍写规则草案永不生效，状态枚举也落后于007迁移；历史导入数量与121项测试通过均不能当作当前数据库事实。后续实现时同步最新有效契约说明。

## 创新性依据与验证设计

RAG 已在 Lewis 等的原始论文中提出；推理与外部工具交替的 ReAct 也已有公开研究。因此，本项目不能仅把“检索数据后回答”和“调用工具”称为新算法。[RAG论文](https://arxiv.org/abs/2005.11401)，[ReAct论文](https://arxiv.org/abs/2210.03629)。这不是完整行业或专利检索，不支持“首创”“领先”等结论。

建议做三组固定案例对照：A 原有页面与通用建议；B 有证据解释；C 有证据解释加数据质量分流、课程匹配和复评资格检查。固定同一模型、温度、输入与数据版本，至少20个分层案例，每组每例3次，由两名评审独立判断。记录关键事实可追溯率、无依据数字率、越权泄露数、低可信分流正确率、任务建议可执行率及p50/p95响应时间。提出100%关键事实可追溯、0泄露、0无确认业务写入作为验收目标，明确这只是有限测试集结果，非所有输入保证。

短期演示只证明闭环能执行和限制能识别，不证明事故率降低。效果评估还需同版本、同暴露量口径与足够后续周期；重叠14天窗口有高度相关性，不宜用相邻两天分值说明培训有效。
