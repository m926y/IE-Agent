# 代码结构与维护说明

默认启动为 Node.js 24 本地工作台。业务数据只读取同级 `IE亮剑`，不将原始数据、运行数据库或账号上传到 GitHub。

| 位置 | 职责 |
| --- | --- |
| `src/` | React 界面；`api.ts` 定义客户端接口，`driver.tsx` 与 `admin.tsx` 组织角色页面 |
| `src/driver-learning.tsx` | 课程阅读、复盘保存和提交 |
| `src/driver-evidence.tsx` | 本人评分、事件和告警的来源证据 |
| `src/learning-report.tsx` | 已保存学习事实及人工复核汇总 |
| `src/training-recovery.tsx` | 管理端培训提醒恢复入口 |
| `server.mjs` | 认证、能力与车队权限、业务接口和状态机；同时保留历史托管入口 |
| `scripts/local-workbench.mjs` | 默认启动入口：启动存储、回环代理、应用子进程及 outbox 工作者，关闭外部模型配置 |
| `scripts/local-broker.mjs` | 仅回环监听的受限 REST 适配层，执行参数化查询和事务写入 |
| `scripts/local-data-store.mjs` | 来源路径校验、CSV 导入、SQLite、技术账号、事务审计及持久 outbox |
| `scripts/build-local-manifest.mjs` | 生成源码、构建和来源文件的哈希清单 |
| `scripts/prepare-publish.mjs` | 构建历史托管兼容制品；不会发布，也不包含本地 SQLite |
| `scripts/contract/` | 历史数据库契约和迁移；不等同于本地 SQLite 初始化 |
| `tests/local-source.test.mjs` | 使用 IE亮剑 文件的真实 SQLite 与业务流程验收 |
| `tests/runtime.test.mjs` | 独立托管兼容制品启动检查 |
| `scripts/source-ui-battery.mjs` | 当前来源限定版本的浏览器验收 |
| `docs/开发记录汇总.md` | 历史开发记录和本次整理记录的统一入口 |

`scripts/r*-battery.*`、`verify-local.mjs`、旧 AI / 通知 / 培训 battery 等属于历史托管环境工具，可能需要远端环境或执行写操作；默认 `npm test` 不会运行它们。保留原路径供历史记录追溯，不能把历史测试数字算入当前本地验收。

维护顺序：修改相应模块，运行 `npm.cmd run typecheck` 和 `npm.cmd test`；页面交互改变时运行当前浏览器验收。之后用 `node scripts/build-local-manifest.mjs` 更新候选清单，并将结果追加到统一开发记录。运行状态只在 `.local/`，隔离测试只在 `.source-tests/`，二者均忽略提交。

来源数据目录不随代码仓库分发。新机器需要把经授权的 `IE亮剑` 文件夹放到项目同级；缺少材料时明确失败，不下载替代数据或生成假业务记录。课程仍需团队人工审核，测试中的临时批准不代表专业审核。
