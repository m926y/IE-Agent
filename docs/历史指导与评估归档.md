# IE Agent 司机端补齐开发与验收指导

> Historical design. Current scope: [local guide](开发与验收指南.md) and [development log](开发记录汇总.md).

版本 V2.0　更新日期 2026年10月28日

适用对象为司机端开发者、后端开发者和验收人员。基线为 main 分支 fe600cc 第37轮脱敏快照。本版结合原指导文档与代码评估，区分已有能力、本轮补齐和后续任务，用于指导可复现开发与双角色验收。

本轮重点是风险记录可查、课程正文可读、学习反馈可保存、权限边界可测试，以及复评条件可说明。已有评分、干预、培训和AI链路继续复用。按用户最新要求，本轮不调整模型接入。

## 一 开发范围和当前结果

| 工作包 | 本轮结果 | 完成条件 |
| --- | --- | --- |
| 本人风险中心 | 新增按日查询，回放事件与人工告警分区 | 本人过滤、北京时间边界、回放标记和错误状态通过 |
| 课程学习 | 任务详情展示正文、版本、完成要求和关联告警 | 仅本人或授权安全管理员可读 |
| 学习反馈 | 支持草稿、反馈和系统使用自检 | 普通记录沿用原表；自检持久化需迁移008 |
| 状态和复评 | 正确区分复核结果，显示本人后续数据限制 | 不因培训完成宣称分数提高或风险下降 |
| 权限和并发 | 已核实绑定校验、旧版本条件更新 | 冲突返回409，不生成成功审计和通知 |

本轮没有接入实时事件流，没有训练模型，没有开展事故率改善实验。新增的两道自检题用于理解评分与复评机制，不代替具体安全课程考试；后续专业情景题必须经课程维护者审核。

### 执行原则

算法事实只读。沿用 alert_id 连接干预与培训，沿用 task_id 连接学习与复核；不能确认的历史关联保留为空。AI生成建议后仍由有权限用户在原业务入口确认执行；ai/confirm只记录采纳关系，不是任务创建接口。

<!-- pagebreak -->

## 二 代码入口与运行方法

司机四个入口位于 src/driver.tsx，全局AI面板位于 src/App.tsx。新增的风险和学习组件放在 src/driver-learning.tsx，接口及类型在 src/api.ts。server.mjs 保持单文件、无额外运行时依赖的发布结构。

### 本地检查

安装 Node.js 22 或更高版本。在项目目录执行以下命令。Windows PowerShell使用npm.cmd，避免npm.ps1执行策略干扰。

    npm.cmd ci --ignore-scripts --no-audit --no-fund
    npm.cmd run typecheck
    npm.cmd run test:driver
    npm.cmd test

build使用Vite runner配置加载器，避免本机esbuild加载配置时遍历父目录失败。运行测试通过Node调用npm CLI，兼容Windows。npm test包括构建、隔离数据库接口测试与独立发布制品健康检查。

### 真实环境前置条件

数据库与账号凭据只通过环境变量提供，不放进仓库。需要可用的SUPABASE_URL、SUPABASE_ANON_KEY和SUPABASE_INSTANCE_ID，以及HOST、PORT；平台部署维持原有SSO配置。不要把脱敏仓库克隆成功等同于已取得可用线上环境。

持久化自检需要先执行 scripts/contract/migrations/008_driver_learning.up.sql。该迁移仅给training_tasks增加course_snapshot与learning_progress两个JSONB列，不更改评分或风险事实。迁移前备份业务表并核对目标数据库；本轮未连接生产数据库执行迁移。

未迁移时，任务详情会明确返回learning_available=false，课程阅读、普通草稿和提交继续可用。保存自检会返回503 learning_migration_required；数据库故障不会被伪装成“未迁移”。down.sql会删除新增列，应先导出学习留存数据再回退。

<!-- pagebreak -->

## 三 风险中心实现与边界

新增GET /api/driver/risk-center?date=YYYY-MM-DD。服务端只接受已核实绑定的司机，由会话决定driver_id，忽略客户端自报身份。未登录返回401，未绑定返回409，待核实或其他角色返回403，日期非法返回400。

接口按北京时间零点到下一日零点查询人工告警；回放事件按本人driver_id和replay_date查询。返回date、timezone、queried_at、latest_replay_date、snapshot、events、alerts和truncated。查询时间不等于数据更新时间，快照日期独立显示。

### 页面要求

回放事件显示时间、事件ID、维度、速度及来源版本；人工告警显示alert_id、evidence_id、发生时间、状态和回放属性。只有evidence_id与本页event_id完全匹配时才提供事件跳转，不能猜测关联。干预沟通继续展示全部日期的已发送记录，明确区别于当天风险列表。

现阶段风险源是历史回放，页面持续显示“历史回放”和“未接入实时事件流”。最新回放日只取本人数据，支持一键切换。未来40天概率来自本人评分快照，不解释成所选日期实时风险，更不能表述成事故已经发生。

### 异常和容量

无事件、无告警、未取得评分快照和查询失败分别处理；不把缺失概率显示为0。每类最多显示100条，多查1条识别截断并提示联系安全员查看完整记录。若未来数据量增大，应增加受控分页，不允许静默截断。

事件表目前以driver_id归属为依据。若后续数据仅有gpsno，必须先通过有效时段绑定核验身份，不能直接用当前车牌关系暴露历史其他司机记录。

<!-- pagebreak -->

## 四 课程学习和任务状态

GET /api/training-tasks/:id扩展课程正文、version_no、source_version、学习快照、自检进度与复评说明。入口校验司机已核实绑定和任务归属；管理端仅允许具备分配培训能力的角色，并校验车队范围。司机不会获得内部审计时间轴。

### 课程版本留存

旧任务没有分配时内容快照，页面如实显示“当前课程版本”。首次成功保存完整自检时，服务端将该课程正文、版本和来源存入course_snapshot，标记captured_stage=first_learning_save；之后即使课程更新或停用，仍能查看这一学习留存版本。不得把首次学习版本描述为分配时版本。

没有留存快照且课程未批准或已停用时，不提供正文；提示联系安全员。此时原有学习记录仍可查看。后续若要严格固定分配时版本，应在分配接口写入快照，并为历史任务保留缺口说明。

### 学习记录和自检

普通草稿保存learning_record与feedback，支持清空，不能用空字符串回退旧值。系统使用自检提供两题：培训是否自动加分，以及缺少新数据能否判断效果。服务端校验答案结构和课程版本，计算correct_count，不信任客户端传来的分数。

自检选择完整时，“保存草稿与反馈”一并持久化；提交前也先保存完整自检，随后调用原提交接口。保存失败不继续提交，输入保留。自检不是课程合格判定，不自动改变任务复核结果。

| 原始状态 | 司机看到的含义 | 下一步 |
| --- | --- | --- |
| assigned / in_progress | 待开始 / 学习中 | 阅读、记录、保存、提交 |
| submitted / returned | 待人工复核 / 需补充 | 等待或按意见补充 |
| reviewed | 复核通过 | 等待可比数据再复评 |
| observation / interview | 继续观察 / 需面谈 | 按安全员意见跟进 |

<!-- pagebreak -->

## 五 并发处理与可信复评

开始、保存、提交和复核均经patchTaskExpected，以task_id、原status和原updated_at作为更新条件，要求数据库返回受影响行。没有命中返回409 task_version_conflict；只有真正成功更新后才写审计或通知。提交后的草稿不能覆盖正文。

该机制依赖所有相关写入同步维护updated_at。外部脚本若绕过版本字段写库，须一并整改。业务更新与后续通知尚未合成数据库事务；数据库网络在提交后中断时，用户应重新查询状态，不能仅根据前端提示推定失败。强一致通知可后续引入事务发件箱。

### 复评数据选择

任务提交后，以北京时间提交日为分界：查询本人在该日前最近的历史记录作为基线，并查询本人在其后最近的记录。不得使用全车队最新日期代替本人有数据的日期，司机与管理员看到同一规则下的结果。

| 条件 | 复评提示 |
| --- | --- |
| 尚未提交或本人没有后续数据 | 等待提交或下一周期数据 |
| 未通过人工复核 | 等待人工复核，仅查看后续记录 |
| 缺基线或来源版本不同 | 不可直接比较 |
| 基线或后续可信度为low | 先核验数据 |
| 提交后不足14天 | 滚动窗口可能包含培训前数据 |
| 以上条件满足 | 仍需人工核验评价口径和覆盖 |

source_version相同只是初筛条件，未证明算法权重版本、暴露量或设备覆盖完全相同。现行规则可受控生效，但历史分值不会自动回算；不能用新权重解释旧分值。本轮因此只给出“待人工核验”的复评结果，不自动判定“改善有效”。

安全分和历史表对空、空白及非有限数显示“—”。历史资源改为服务端倒序取最近20条，前端再按时间顺序展示，避免记录超过20条后误取最早20条。近14天滚动分不重命名为周评分。

<!-- pagebreak -->

## 六 验收安排与后续创新

隔离接口测试覆盖身份和对象越权、北京时间边界、无数据、查询故障、100条截断、最新历史、课程版本留存、反馈保存、缺迁移降级、并发冲突、提交幂等及复评分流。隔离库验证接口行为，不能代替真实PostgreSQL约束和多角色部署验收。

### 上线前双角色验收

1. 在测试库执行008迁移，用两个不同司机账号确认风险、任务与课程留存不能互读。
2. 安全员分配已批准课程；司机读取正文、自检、保存，刷新后确认记录与反馈一致。
3. 司机提交后验证不可再编辑；安全员分别测试通过、退回、观察和面谈。
4. 在两浏览器同时保存或提交同一任务，确认冲突不会覆盖提交记录，也不会重复发通知。
5. 核验真实数据库source_version含义与评价窗口，确认没有新数据时只显示等待复评。
6. 390像素窄屏与桌面各检查一次，记录候选版本、截图、接口回执与已知限制。

### 创新主线

建议把项目创新描述为“基于证据和数据质量的改善分流”：低可信先核验设备与数据；证据充分时解释主要维度，匹配人工批准课程；任务完成后检查本人新数据与可比性，再由安全员复评。AI承担解释和个性化草稿，权限、评分、状态与执行回执继续由系统控制。

工具调用与检索生成已有公开研究，不宜单独宣称算法首创。后续用固定案例比较“通用建议”“证据解释”“证据解释加质量分流”，记录事实可追溯率、越权泄露数、无依据数字率、建议可执行率与响应时间。目标是有限测试集100%关键事实可追溯、0泄露、0未确认业务写入，不以演示结果推断事故率下降。

### 下一轮任务

优先增加分配时课程快照与经审核的专业情景题，再完善风险列表分页和历史评分分页；为司机提供可验权的原始证据详情；补充评分产生时的规则版本、有效覆盖与暴露量字段。所有新增字段经迁移和真实数据验证后再用于自动可比性判断。改善计划表与自动推荐排序应在这些基础齐备后引入。

参考研究：Lewis等《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》，https://arxiv.org/abs/2005.11401；Yao等《ReAct: Synergizing Reasoning and Acting in Language Models》，https://arxiv.org/abs/2210.03629。项目评估详见review目录中的可行性与创新性评估。

无事件、无告警、未取得评分快照和查询失败分别处理；不把缺失概率显示为0。页面每类显示20条，多查1条判断下一页，回放和告警独立翻页；日期变更同时重置到第一页。采用时间与稳定ID排序，静态数据中不漏页；若列表翻页期间有新数据写入，offset分页位置可能移动，用户可回到第一页刷新。后续高频实时流可改为游标分页。

事件表目前以driver_id归属为依据。若后续数据仅有gpsno，必须先通过有效时段绑定核验身份，不能直接用当前车牌关系暴露历史其他司机记录。

<!-- pagebreak -->

## 四 课程学习和任务状态

GET /api/training-tasks/:id扩展课程正文、version_no、source_version、学习快照、自检进度与复评说明。入口校验司机已核实绑定和任务归属；管理端仅允许具备分配培训能力的角色，并校验车队范围。司机不会获得内部审计时间轴。

### 课程版本留存

新分配从已批准课程中读取正文、完成要求、version_no与source_version，在创建training_tasks同一次写入中保存course_snapshot，标记captured_stage=assignment。课程后续更新或停用不会覆盖任务的留存版本；页面同时展示当前课程状态，避免把历史批准状态当成现状。

旧任务没有分配时快照，仍显示“当前课程版本”；首次成功保存完整自检时可留存first_learning_save版本，不能补称为分配时版本。没有留存且课程未批准或已停用时不提供正文，提示联系安全员，原有学习记录仍可查看。

通知模板和已核实身份在创建任务前校验，避免无效模板报错后留下任务。同一分配幂等键绑定课程、司机和告警，改绑返回409 assignment_idempotency_conflict；课程后来停用不影响读取原有同一任务。通知写入与任务写入仍不在同一数据库事务内，不把模板预检改进描述成事务化完成。

### 学习记录和自检

普通草稿保存learning_record与feedback，支持清空，不能用空字符串回退旧值。系统使用自检提供两题：培训是否自动加分，以及缺少新数据能否判断效果。服务端校验答案结构和课程版本，计算correct_count，不信任客户端传来的分数。

自检选择完整时，“保存草稿与反馈”一并持久化；提交前也先保存完整自检，随后调用原提交接口。保存失败不继续提交，输入保留。自检不是课程合格判定，不自动改变任务复核结果。

| 原始状态 | 司机看到的含义 | 下一步 |
| --- | --- | --- |
| assigned / in_progress | 待开始 / 学习中 | 阅读、记录、保存、提交 |
| submitted / returned | 待人工复核 / 需补充 | 等待或按意见补充 |
| reviewed | 复核通过 | 等待可比数据再复评 |
| observation / interview | 继续观察 / 需面谈 | 按安全员意见跟进 |

## 五 并发处理与可信复评

开始、保存、提交和复核均经patchTaskExpected，以task_id、原status和原updated_at作为更新条件，要求数据库返回受影响行。司机页面的开始、保存和提交额外携带expected_updated_at，避免旧窗口在另一个窗口保存后继续覆盖。保存回执使用数据库实际返回的时间戳表示，供紧接着的提交使用，兼容数据库对时区格式的转换。

冲突返回409 task_version_conflict，输入和自检选择保留，保存与提交按钮暂停；用户读取最新任务状态后，可展开服务器已保存内容进行核对，再决定保存。开始学习后自动刷新不会覆盖未保存输入或重置自检选项。旧客户端未传expected_updated_at时仍兼容原接口，仅享有服务端请求期间的条件更新保护；部署时应同步更新前端。

该机制依赖所有相关写入同步维护updated_at。外部脚本若绕过版本字段写库，须一并整改。业务更新与后续通知尚未合成数据库事务；数据库网络在提交后中断时，用户应重新查询状态，不能仅根据前端提示推定失败。强一致通知可后续引入事务发件箱。

### 复评数据选择

任务提交后，以北京时间提交日为分界：查询本人在该日前最近的历史记录作为基线，并查询本人在其后最近的记录。不得使用全车队最新日期代替本人有数据的日期，司机与管理员看到同一规则下的结果。

| 条件 | 复评提示 |
| --- | --- |
| 尚未提交或本人没有后续数据 | 等待提交或下一周期数据 |
| 未通过人工复核 | 等待人工复核，仅查看后续记录 |
| 缺基线或来源版本不同 | 不可直接比较 |
| 基线或后续可信度为low | 先核验数据 |
| 提交后不足14天 | 滚动窗口可能包含培训前数据 |
| 以上条件满足 | 仍需人工核验评价口径和覆盖 |

source_version相同只是初筛条件，未证明算法权重版本、暴露量或设备覆盖完全相同。现行规则可受控生效，但历史分值不会自动回算；不能用新权重解释旧分值。本轮因此只给出“待人工核验”的复评结果，不自动判定“改善有效”。

安全分和历史表对空、空白及非有限数显示“—”。历史资源按日期与score_id倒序分页，第一页最近20条，支持查看更早记录和返回较新记录；页内按时间顺序展示并列出来源版本。六维说明标注“本页最近一日”，避免历史页误作当前快照；读取失败可重试。近14天滚动分不重命名为周评分。

## 六 验收安排与后续创新

隔离接口测试覆盖身份和对象越权、北京时间边界、无数据、查询故障、100条截断、最新历史、课程版本留存、反馈保存、缺迁移降级、并发冲突、提交幂等及复评分流。隔离库验证接口行为，不能代替真实PostgreSQL约束和多角色部署验收。

### 上线前双角色验收

1. 在测试库执行008迁移，用两个不同司机账号确认风险、任务与课程留存不能互读。
2. 安全员分配已批准课程；司机读取正文、自检、保存，刷新后确认记录与反馈一致。
3. 司机提交后验证不可再编辑；安全员分别测试通过、退回、观察和面谈。
4. 在两浏览器同时保存或提交同一任务，确认冲突不会覆盖提交记录，也不会重复发通知。
5. 核验真实数据库source_version含义与评价窗口，确认没有新数据时只显示等待复评。
6. 390像素窄屏与桌面各检查一次，记录候选版本、截图、接口回执与已知限制。

### 创新主线

建议把项目创新描述为“基于证据和数据质量的改善分流”：低可信先核验设备与数据；证据充分时解释主要维度，匹配人工批准课程；任务完成后检查本人新数据与可比性，再由安全员复评。AI承担解释和个性化草稿，权限、评分、状态与执行回执继续由系统控制。

工具调用与检索生成已有公开研究，不宜单独宣称算法首创。后续用固定案例比较“通用建议”“证据解释”“证据解释加质量分流”，记录事实可追溯率、越权泄露数、无依据数字率、建议可执行率与响应时间。目标是有限测试集100%关键事实可追溯、0泄露、0未确认业务写入，不以演示结果推断事故率下降。

### 下一轮任务

下一轮可增加经审核的专业情景题、可验权的原始证据详情，补充评分产生时的规则版本、有效覆盖与暴露量字段，并为高频数据评估游标分页。任务分配、通知和审计的事务化或事务发件箱需要真实数据库设计验证。所有新增字段经迁移和真实数据验证后再用于自动可比性判断。改善计划表与自动推荐排序应在这些基础齐备后引入。

参考研究：Lewis等《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》，https://arxiv.org/abs/2005.11401；Yao等《ReAct: Synergizing Reasoning and Acting in Language Models》，https://arxiv.org/abs/2210.03629。项目评估详见review目录中的可行性与创新性评估。

## 五 并发处理与可信复评

开始、保存、提交和复核均经patchTaskExpected，以task_id、原status和原updated_at作为更新条件，要求数据库返回受影响行。司机页面的开始、保存和提交额外携带expected_updated_at，避免旧窗口在另一个窗口保存后继续覆盖。保存回执使用数据库实际返回的时间戳表示，供紧接着的提交使用，兼容数据库对时区格式的转换。

冲突返回409 task_version_conflict，输入和自检选择保留，保存与提交按钮暂停；用户读取最新任务状态后，可展开服务器已保存内容进行核对，再决定保存。开始学习后自动刷新不会覆盖未保存输入或重置自检选项。旧客户端未传expected_updated_at时仍兼容原接口，仅享有服务端请求期间的条件更新保护；部署时应同步更新前端。

该机制依赖所有相关写入同步维护updated_at。外部脚本若绕过版本字段写库，须一并整改。业务更新与后续通知尚未合成数据库事务；数据库网络在提交后中断时，用户应重新查询状态，不能仅根据前端提示推定失败。强一致通知可后续引入事务发件箱。

### 培训提醒的独立回执

分配和提交在业务写入成功后，返回notification.state。recorded表示站内通知已记录，pending表示提醒待恢复，no_recipient表示无有效授权接收账号，not_needed表示任务已进入后续阶段，无需补发旧提醒。客户端分别显示业务与提醒结果，不把提醒失败解释为任务未保存。

重复分配或重复提交可恢复同一阶段提醒。安全员也可在培训台账“站内提醒故障恢复”中输入task_id，调用POST /api/training-tasks/:id/retry-notification，kind为assigned或submitted。服务端核验assign.training能力与车队范围，自行决定正文和接收人；不接受任意接收账号。提醒唯一键冲突时返回已有回执，不重复记录。

该机制是应用层幂等恢复，不是后台自动重试作业，也不是跨表事务；第五轮仍需真实数据库验证和一致性方案。

### 复评数据选择

任务提交后，以北京时间提交日为分界：查询本人在该日前最近的历史记录作为基线，并查询本人在其后最近的记录。不得使用全车队最新日期代替本人有数据的日期，司机与管理员看到同一规则下的结果。

| 条件 | 复评提示 |
| --- | --- |
| 尚未提交或本人没有后续数据 | 等待提交或下一周期数据 |
| 未通过人工复核 | 等待人工复核，仅查看后续记录 |
| 缺基线或来源版本不同 | 不可直接比较 |
| 基线或后续可信度为low | 先核验数据 |
| 提交后不足14天 | 滚动窗口可能包含培训前数据 |
| 以上条件满足 | 仍需人工核验评价口径和覆盖 |

source_version相同只是初筛条件，未证明算法权重版本、暴露量或设备覆盖完全相同。现行规则可受控生效，但历史分值不会自动回算；不能用新权重解释旧分值。本轮因此只给出“待人工核验”的复评结果，不自动判定“改善有效”。

安全分和历史表对空、空白及非有限数显示“—”。历史资源按日期与score_id倒序分页，第一页最近20条，支持查看更早记录和返回较新记录；页内按时间顺序展示并列出来源版本。六维说明标注“本页最近一日”，避免历史页误作当前快照；读取失败可重试。近14天滚动分不重命名为周评分。

- 对回复、复核申请设置请求中状态和重复点击保护；显示服务端错误及成功记录引用。保留已有字数限制，补充计数和服务端截断行为的一致说明。
- 修正课程版本 `0` 被 `version_no || "未取得"` 隐去的问题；缺失用空值判断，来源导入基线 0 应正常显示。

退出条件：未保存切页、刷新及保存失败可明确判断是否丢失；快速重复点击不重复写业务；390px 与桌面均可完成阅读、保存、刷新、提交、退回补充和复核查看；无横向溢出，加载、空、无权限与失败可区分。

### 第九轮 形成有证据的司机行动闭环

优先级 P1，预计 3—4 人日。修改重点为 `src/driver.tsx`、新建小型展示模块、`src/api.ts` 和 `server.mjs` 的只读聚合服务。

- 先增加只读的本人行动摘要，返回待处理培训、本人已发送干预和复核状态，以及来源截止日。计数应服务端查询完整范围，不用当前分页条数冒充总量。
- 时间线优先从任务、已发送干预、本人复核和来源记录聚合，返回 `event_type/source_kind/source_id/event_at/status/source_version`。身份取会话；内部管理审计不直接转发。
- 使用稳定 ID 和时间排序及明确分页契约。不同对象仅在真实 alert_id/task_id 等关系存在时连接；通用培训没有告警则显示独立任务，不能按日期接近猜测因果。
- 为分配、开始、提交、退回、复核等真实节点提供下一步入口；未记录历史节点就说明缺失，不从当前状态反推完整过去。
- 评分变化只比较实际存在的两期，展示来源版本、滚动窗口和覆盖限制；六维缺失时不绘制暗示零值的条形。缺少足够周跨度则不显示四周趋势，不另造周评分。
- 对车队均值增加有效数值及版本一致性审查；展示有效样本定义。小样本或可反推个体的分组继续抑制，不开放司机排名。

退出条件：每个摘要和时间线节点可跳转至重新验权的真实详情；无关系不串案、无后续数据不画改善结果；分流提示与已有复评规则一致；新接口不能输出其他司机及管理审计字段。当前本地模式仍无外部 AI 请求。

### 第十轮 验证改进价值并形成可复核候选

优先级 P1，预计 2—3 人日。交付为当前来源浏览器验收扩展、指标记录、已知限制及候选哈希清单。

- 按前述 A/B/C 对照完成实际支持的案例，记录数据版本、任务说明、评审方法及原始结果；没有人工参与则不宣称用户验证完成。
- 扩展当前 `source-ui-battery.mjs`，覆盖权限退化、未保存输入、并发冲突、缺失及错误、本人证据跳转和新时间线。只在新建 `.source-tests/` 库执行课程临时审批。
- 冻结候选后执行类型检查、默认测试、页面验收和清单生成，记录对应提交及工具版本。既有运行库保留原状态，测试审批不得复制过去。
- 整理一次司机与安全员完整操作的真实记录，以及无告警、课程未审核、没有新评分时的诚实演示路径。

退出条件：类型与默认测试通过；本轮新增页面场景通过；有限案例中关键事实可追溯率目标 100%、跨司机泄露 0、未授权业务写入 0、缺数被误表述为零风险 0。查找耗时和理解改善按实际结果报告，不预设提升百分比。没有真实课程审核时，候选仍只能证明技术工作流可运行，不能称正式培训内容验收完成。

## 开发与验收纪律

每轮交付应包含具体问题、最终行为、代码位置、针对性验证、未覆盖情况及回退方法，并统一追加到 `docs/开发记录汇总.md`。出现新字段时同时更新 API 类型及本地数据契约；不为未来假设提前增加新表。

每轮执行 `npm.cmd run typecheck` 与 `npm.cmd test`；页面流程变化后执行 `node scripts/source-ui-battery.mjs`，使用已有且可导入的 Playwright/Chromium 环境；构建后执行 `node scripts/build-local-manifest.mjs`。不能自动运行可能连接远端或写入的历史 battery。

新功能可通过保留旧入口、撤回新增路由或可关闭展示实现回退。涉及数据结构时须事先验证保留数据的升级及回退路径，不能通过删除运行库恢复。任何账号、密钥、数据库、测试状态或构建产物均不提交。

若窗口只够两轮，应先完成第七轮和第八轮，将第三轮缩为一个可追溯的行动摘要。优先保住权限与数据正确性、司机记录和真实回执。课程人工审核可以同期由团队完成，但开发者不得代为批准。外部 AI、实时流、远端部署和培训效果研究均保留为独立后续范围。
