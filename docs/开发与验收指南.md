# 开发与验收指南

现行开发维护、本地使用和验收的统一入口。第十轮按用户选择完成技术验收与评审材料，真实人工评审后补；最终证据与限制见[第十轮验收与评审](第十轮验收与评审.md)。历史设计仅用于追溯。

## 代码与维护


默认启动为 Node.js 24 本地工作台。业务数据只读取同级 `IE亮剑`，不将原始数据、运行数据库或账号上传到 GitHub。

维护顺序：修改相应模块，运行 `npm.cmd run typecheck` 和 `npm.cmd test`；页面交互改变时运行当前浏览器验收。之后用 `node scripts/build-local-manifest.mjs` 更新候选清单，并将结果追加到统一开发记录。运行状态只在 `.local/`，隔离测试只在 `.source-tests/`，二者均忽略提交。

来源数据目录不随代码仓库分发。新机器需要把经授权的 `IE亮剑` 文件夹放到项目同级；缺少材料时明确失败，不下载替代数据或生成假业务记录。课程仍需团队人工审核，测试中的临时批准不代表专业审核。


## 本地使用与验收


当前候选按“只使用IE亮剑资料”收敛。本文替代V2系列指导文档中关于新增专业题库、外部AI、远端数据库联调的待办要求；旧文档保留作历史记录，不作为当前数据来源。

## 启动和账号

本机使用Node.js 24验证。项目依赖已经安装，双击项目根目录“启动本地工作台.cmd”，或执行npm.cmd start。默认地址为http://127.0.0.1:3100。首次运行读取来源文件并创建SQLite，后续运行读取已有状态，不覆盖操作记录。

账号文件位于IE-Agent/.local/accounts.json。local_admin为本地联调管理员；local_driver和local_other分别绑定到来源drivers.csv中的不同演示司机。口令随机生成并只写本地文件，不在文档中硬编码。技术账号与会话用于访问控制，不构成新的真实司机或算法结果。

如需独立环境，可设置LOCAL_STATE_DIR为本工作区中的另一个目录；LOCAL_PORT可改本地端口。不要覆盖已有目录来重置；使用新目录保留旧数据。源文件发生变化时，程序会拒绝静默覆盖旧库，应先核对来源再建立独立新库。

## 来源与功能边界

| 项目 | 当前处理 |
| --- | --- |
| 风险、评分、历史、台账、回放 | 仅导入IE亮剑/outputs/agent_starter/import，保留逐文件哈希和行数 |
| 三门来源课程 | 保留正文和原待审核状态；人工明确批准后才可分配 |
| 专业测验和学习自检 | 来源无题库及答案，已从界面和服务移除；旧请求返回410 |
| 学习复盘汇总 | 只整理课程、本人记录、反馈和真实人工复核意见，不生成新专业结论 |
| 外部模型和数据服务 | 默认本地模式关闭入口并阻断API，不发生模型调用 |
| 实时风险和效果证明 | 不提供；页面明确历史回放，缺少新数据时等待复评 |
| 外部导入、新课程文本及知识内容写入 | 本地来源策略拒绝；原文件不被业务操作改写 |

CSV中的空值保持缺失语义，不自动变为零风险。课程版本0代表文件导入基线，后续审核版本为本地工作流元数据；来源哈希始终关联原文件。

## 课程和司机闭环

管理员在“培训管理—课程库与审核”查看原课程，提交审核并明确确认批准。此操作需要团队自行核对内容，程序不会代替专业审核。批准后在“创建培训”选择司机和课程，填写目标与截止时间；没有来源告警时可作为通用培训，不能伪造风险关联。

司机进入“培训任务”，阅读分配时留存的课程正文，填写复盘和反馈，保存后刷新可恢复。提交后由管理员在台账复核，可以退回补充或通过。司机点击“查看学习复盘汇总”会读取最新记录并刷新任务状态。

三个来源课程都是演示课程，没有专业审核证明。验收脚本只在隔离测试库里执行批准和分配流程，干净候选库仍保持零任务与三门待审核课程。

第八轮把风险导航统一为“历史风险与沟通”，不表示接入实时风险。培训卡片区分未保存与操作中状态，显示学习记录6000字、反馈3000字上限及当前计数。课程版本0正常显示，不再当作缺失值。

有未保存学习记录时，切换司机页签或培训分页会提供“留在当前页”“保存后离开”和“放弃未保存内容并离开”。保存失败或冲突未处理时不会离开；放弃只丢弃尚未保存的页面输入，不修改服务器记录。刷新任务列表失败不卸载已有草稿，列表顺序变化时也保留尚未保存或正在处理的任务。多个草稿分别保存，不构成一次数据库事务。

版本冲突时先重新读取状态，页面仍保留本人输入，并可查看服务器内容；核对后明确选择保留本人输入继续编辑或采用服务器内容。单纯重新读取不会自动允许覆盖。回复和复核申请在请求进行中禁用重复提交与输入修改，失败时保留输入并提示先查询状态；成功展示实际保存回执。

浏览器刷新、关闭或离开站点使用浏览器原生未保存提示，本次Chromium验证了取消刷新后输入仍保留。应用不自动提交、不将草稿写入浏览器持久存储；浏览器或系统强制关闭、会话失效以及用户确认丢弃后，不能保证恢复未保存内容。离开前应主动保存。

## 本人行动摘要与证据闭环

第九轮在“我的安全”增加“我接下来做什么”：按完整查询范围显示待完成培训、培训待复核/跟进、待回复沟通及评分复核状态。低可信或缺少评分口径时先提示核验；没有待办不表示零风险。点击摘要进入本人的业务入口，不自动分配课程或修改评分。

展开“查看本人业务时间线”可查看真实保存的节点，并打开重新验权的评分、回放、告警、培训、沟通或复核详情。内嵌培训可以继续阅读、保存和提交，并沿用未保存保护；内嵌沟通只提供已发送正文及本人回复。通用培训没有真实告警关联时独立显示；有关联时只沿本人精确ID关系跳转，不以日期接近拼接案例。

时间线不是完整历史日志：只使用业务字段，展示分配快照、首次开始、最近提交和当前保存的复核时间等已有事实，不开放管理审计。旧任务缺少分配时间、往返退回历史被覆盖时不补造节点。评分截止日按日期显示，不表示当天零点发生过风险事件。

“两期评分变化核对”默认选本人最近两个不同截止日，允许从最近50条真实历史中重新选择较早/较晚记录。展示分数、六维、评价窗口、来源版本及评分方法；版本或方法不一致/缺失、分值或可信度不足时不计算差值。窗口重叠时明确限制，任何数值差都不构成培训有效判定。当前来源只有2026-07-24至2026-07-31八个截止日，不能展示不存在的四周趋势。

匿名车队统计要求同车队、同截止日、可用状态、有限数值、有效司机记录唯一，并检查版本与方法一致性。样本不足10时隐藏人数、均值及分布；细分等级可能反推个体时隐藏分布。混版本或缺少口径时不混算均值，不提供其他司机明细或排名。

### 新只读接口

| 接口 | 契约与限制 |
| --- | --- |
| GET /api/driver/action-center | 当前会话本人；默认每页10节点，limit为1—50；cursor用于更早节点。计数不随节点分页缩小。业务节点变化导致游标失效时返回409 action_center_changed，须从第一页刷新 |
| GET /api/driver/score-comparison | 当前会话本人；不传参数时选择最近两个不同截止日。指定时同时传before_id和after_id，必须属于本人历史且截止日有先后顺序 |
| GET /api/driver/intervention?id=… | 当前会话本人且已发送的沟通；不输出内部草稿、创建人或任意关联记录 |

新接口均要求已核实司机绑定，忽略客户端自报driver_id；无权限与不存在的对象使用统一拒绝语义。来源查询失败返回错误，不改成空摘要。聚合按稳定主键分批读取，单表超过100000条明确失败，不截断冒充完整计数。接口跨多次受限REST读取，不承诺多表同一数据库事务快照；读取或翻页期间数据变化时应刷新核对。

## 数据库与故障恢复

SQLite包含真实主键和幂等键唯一约束。任务创建或提交时，数据库触发器在同一事务中记录待发提醒和技术事务审计。后台每秒处理待发项，通知记录、处理审计及完成标记在同一事务中提交；重启后继续处理未完成项。

第七轮增加复核申请的 `review_outbox`：创建申请，以及答复/关闭时，在业务事务内记录提醒；后台处理失败后保留待发送状态、尝试次数和技术错误码，约30秒后重试。单项失败不会阻塞本轮其他到期提醒。接收账号第一次确定后固定；账号停用、司机绑定失效或车队范围变化时不改投其他账号。过期阶段的提醒跳过。接口的 `notification` 与业务成功结果分开返回，`pending` 不表示申请或答复保存失败。

首次用新代码启动已有库时，只追加表和触发器，并补记尚在 submitted/checking/awaiting_data_owner 阶段的既有申请提醒，不覆盖申请、评分、课程和历史审核；已答复或关闭的旧申请不追造历史答复提醒。三门来源课程不会因此变为已批准。

本人业务入口要求当前账号有已核实司机绑定，包括评分复核详情、创建申请、干预已读/回复及站内业务通知。账号自己的联系方式和偏好与业务身份分开，未绑定司机仍可维护自己的资料，不能修改身份、角色或评分。管理员读取和处理复核、编辑和发送干预时也按车队范围校验。

账号不可达或接收人变化时不擅自改投；保留待处理状态。已有任务阶段变化时跳过过期提醒。应用层人工审计仍保留，技术事务审计不冒充用户审核意见。本地SQLite实现不等同于此前托管PostgreSQL实现；没有对远端库运行SQL迁移或做公网部署。

## 验收与候选清单

npm.cmd test执行真实来源文件、SQLite唯一约束、事务回滚、重启恢复、权限和学习汇总测试，并验证独立构建制品。此前的虚构业务夹具已删除，历史测试数量不能与当前来源验收数量直接累计。

浏览器脚本为scripts/source-ui-battery.mjs，需要可导入的Playwright和本机Chromium类浏览器。可用PLAYWRIGHT_MODULE、BROWSER_EXECUTABLE、QA_OUTPUT_DIR指定已有工具和截图目录。脚本记录页面异常、HTTP失败和外部请求；不会连接真实外部服务。

本次验收工具位于忽略提交的 `.source-tests/browser-tools/`。项目依赖版本和依赖锁保持不变，package.json新增了验收命令。可在PowerShell中复用：

```powershell
$env:PLAYWRIGHT_MODULE = (uri（历史路径 `Join-Path (Get-Location`） '.source-tests/browser-tools/node_modules/playwright/index.mjs')).AbsoluteUri
$env:BROWSER_EXECUTABLE = (Get-ChildItem .source-tests/browser-tools/browsers -Recurse -Filter chrome.exe | Select-Object -First 1).FullName
node scripts/source-ui-battery.mjs
```

当前浏览器覆盖培训保护、证据跳转、行动摘要、权限变化及会话恢复。预期HTTP失败单独记录；默认测试、浏览器组数和案例对照分别报告，最新实测数字统一见[第十轮验收与评审](第十轮验收与评审.md)。截图和browser-result.json仅在隔离目录，临时审批和任务不得复制到运行库。

scripts/build-local-manifest.mjs生成代码、构建文件和来源哈希清单，位于driver/review/local-candidate-manifest.json。该清单是可复核记录，不是数字签名。根目录默认启动的是本地数据模式；.qw-pages中的托管兼容制品仅保留独立启动验证，不包含本地SQLite或账号，不作为此次公网交付。

第七轮起，清单生成使用 `.source-tests/manifest-*` 中全新的隔离来源库，不打开 `.local`。清单的 `clean_state` 表示来源初始状态，不表示用户运行库当前状态；账号和隔离库均不提交。
