# 管理员、安全员、历史当班与模型规则

入口：系统管理的司机车辆绑定页新增历史当班查询和补录；管理员在规则与运营配置中维护权重及模型因子。

## 角色

- 原 `safety_admin` 兼容保留，界面明确称“管理员”。已有 `preview_admin` 仍是管理员。
- 新 `safety_officer` 是安全员。管理员可在账号管理选择该角色创建账号。安全员保留评价、风险、聊天、培训及司机绑定等业务操作；不显示模型配置控件或规则草案页。服务端拒绝读取/预览/提交全局模型配置。
- 账号授权和数据导入由管理员负责，防止安全员通过创建管理员或导入评分数据绕过模型权限。司机、队长权限延续。

## 历史当班API

- `GET /api/admin/duty-history?gpsno=...&at=2026-07-08T13:05:33%2B08:00`：按准确时点查询；不传时点查询历史，不传车辆查询授权范围。
- `POST /api/admin/duty-history`：补录已核实历史，字段 `user_id,gpsno,start_at,end_at,note`，带时区ISO时间；结束必须晚于开始且不晚于现在，依据必填。
- 原 `POST /api/admin/vehicle-binding`：沿用 `user_id,gpsno`；`gpsno:null` 解绑。关闭旧区间、写入新区间、更新权限及审计在同一事务完成，保留SSO身份映射。
- 表 `driver_duty_history`，区间为左闭右开 `[start_at,end_at)`。同时同车只对应一个司机，同一司机同时只对应一辆车。解绑及换绑保留旧记录，历史补录不改变当前权限。
- 首次启动从迁移时刻记录已核实的当前绑定；其余车辆按用户授权初始化一车一司机档案（标注默认假设，不创建登录账号），不猜测更早当班身份。更早历史可凭实际依据补录；无记录返回 `unknown`。管理端案卷显示事件发生时的历史当班司机，与当前消息接收绑定区分。

## 模型规则

管理员可修改24个已知事件因子的名称、所属行为维度和严重度；六维权重；1—30天观察窗口、1—60天半衰期；五个事件维度的参考先验τ、μ及初赛参考分布尺度。

这是对现有六维/24个已知事件体系的配置，不支持任意Python公式或未知事件码。IMU独立计算口径保留。参考尺度1沿用初赛参考分布，修改后实际参与百分位换算。

模型规则先从原始清洗parquet重新计算500辆车和8日历史并显示影响，预览不生效；确认后事务保存新模型配置、评分、排名、台账、队列及版本归档。恢复历史版本同时恢复对应模型规则和评分。事故预测输出不随评价规则改动而重训。

HTTP重算使用异步子进程，计算期间其他聊天/风险请求可以继续处理；预览会缓存本次计算结果供确认使用。评分版本变化则旧预览失效。

## 依赖与运行

本地沿用 `node scripts/start-local.mjs`。模型规则重算依赖原初赛清洗数据及Python的pandas、numpy、scipy、scikit-learn、pyarrow和duckdb；本机DuckDB沿用 `.runtime-tmp/python`。

部署其他环境需配置 `MODEL_PYTHON`（Python可执行文件）和 `SCORING_DATA_ROOT`（包含data/processed/cleaned的初赛项目根目录），安装上述依赖。发布包已增加评分Python源码和重算脚本；数据与运行依赖需另行准备，不能仅传静态前端。

新增测试 `tests/model-duty.test.mjs` 验证历史区间、换绑冲突、未知历史、实际重算与恢复；`tests/full-data.test.mjs` 增加安全员业务访问、模型越权和管理员授权防线的HTTP检查。

升级前备份：`var/before-role-model-duty-20261030.sqlite`。本次没有将新规则应用到实际业务评分，也没有修改已有账号角色或补造历史当班记录；启动时初始化当前已核实绑定及其余车辆的默认一车一司机档案。
