## 校验与权限

- 7 月 31 日重现评分与正式 CSV 最大差值为 **0**；分摊台账与评分扣分最大误差约 `1.42e-14`。
- 原 `driving-safety-agent/var/history.sqlite` 以 `mode=ro` 挂载，未改写原始索引。
- 司机仅查询本人车辆；未核实绑定不能读取本人明细。受限安全员/队长的列表、计数及数据中心统计也受车队范围约束。
- 本地数据库网关只监听 loopback，使用随机私有 token，token 不下发浏览器；模型没有 SQL 执行接口。
- 评分、历史、预测及原始索引的读取不执行在线重算。运营写入继续走平台的角色、确认和审计接口。
- 修改规则草案的窗口值为空时保留原窗口，修复了只改权重却将 14 天改成 1 天的问题。

## 启动与入口

本地数据库模式使用 **Node.js 24+**。已经构建时运行：

```powershell
npm run start:local
```

默认地址：`http://127.0.0.1:3100/`。修改端口可设置 `LOCAL_PORT`。

2026-10-29 模型配置：`start:local` 会读取项目根目录的 `.env.local`（已被 Git 忽略），使用 `QW_AI_BASE_URL`、`QW_AI_MODEL`、`QW_AI_API_KEY` 配置外部模型。目前接入 `qwen3.7-plus`，Base URL 为 `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`。密钥仅在服务端读取，不写入前端或说明文件。修改后重启本地服务生效；已有系统环境变量优先。

模型接口与平台完整查询链路均已验证；对话执行创建账号、批量培训等新写操作本轮尚未启用，仍使用现有草稿及页面提交流程。

- 安全员“数据总览/车队管理”：500 辆评分、预测、排名和趋势。
- “数据中心”：全量数据清单、事件分页、日汇总和画像；支持车辆及日期筛选。
- “历史事件回放”：可选择全部 500 辆车中的任意车辆和 6—7 月日期，读取该车当天全部事件；仍是历史显示回放，不自动生成告警。
- 司机“我的安全→历史事件与车辆数据”：本人事件及日汇总。

`npm start` 保留原云端/PostgREST 启动方式；`npm run preview:accounts` 仍是单独的空业务测试环境，**不应作为完整数据平台启动方式**。

本地建库程序已包含 S1 所需字段，不需要向 SQLite 手动执行 PostgreSQL 的 008/009 迁移。云端接入需另行迁移 schema 和数据，本轮没有上传或发布线上平台。

## 数据与备份位置

- `var/platform.sqlite`：当前业务数据与账号、会话、头像、状态、审计。
- `var/data-manifest.json`：数量、覆盖日期、评分及台账校验。
- `var/legacy-preview-backup.json`、`var/before-switch-*.sqlite`：切换前备份，含账号敏感信息，已被 Git 忽略，不应公开上传。
- `../driving-safety-agent/var/history.sqlite`：已有的只读历史索引，无需重复复制 784MB。

不要删除这些文件来“刷新界面”。重启会保留资料和业务记录，不会重新生成账号或重建评分。

## 重建与测试

建库工具为 `scripts/build-full-data.py`，依赖 pandas、numpy、pyarrow、scipy、scikit-learn、duckdb 及工作区已有的清洗 parquet、正式 CSV、历史索引。冻结算法及配置保存在 `scripts/scoring_source/`。本机 DuckDB 安装在 `.runtime-tmp/python`，没有改动系统包。

建库命令为 `node scripts/export-local-schema.mjs`、`python scripts/build-full-data.py`，仅适用于尚未建立评分版本的数据库；已经启用 S2 的业务库会拒绝覆盖重建。新数据源应另建独立基线，先保留当前库及评分版本。这不是日常启动步骤。评分历史缓存的指纹包含正式 CSV 与冻结配置，发现无法重现正式分数时会中止。

```powershell
node --test tests/accounts.test.mjs tests/full-data.test.mjs
```

26 项测试覆盖账号、500 车跨页、A—D 等级、8 个历史日期、全量源数据计数、AI 工具分页、司机越权、车队范围、私有网关、只读事实和重启持久化。测试复制业务库后执行，不改写现有平台库，不调用模型。

本轮只接数据，模型仍保留原外部接口；没有改回本地模型，也没有自动配置或调用付费模型。

## 司机与车辆绑定（本轮完善）

在系统管理的“司机档案与车辆绑定”选择已启用的司机登录账号及“车辆1”等展示名称，即时绑定或更换车辆。司机侧读取该车评分、风险及历史事件；新建账号需要先完成首次改密。绑定控制当前数据访问，不修改数据集 drivers、历史评分与事件归属。

支持解除绑定并同步移除本人明细权限；旧关系留作历史，不再物理删除。已占用车辆拒绝重复绑定；普通司机不能执行管理操作；安全员账号不能充当司机绑定。司机端刷新或15秒内同步变更，并清除旧车辆AI会话。测试在数据副本上进行，没有擅自调整现有账号实际绑定。
