# 安全员与司机消息交流

点击两端页面顶部的“消息”，选择联系人即可开始双向对话；同一窗口的“系统通知”保留原培训、风险等站内通知。

- 在线会话每1秒自动获取新消息，联系人及未读角标每2秒刷新；通过短轮询实现，需要页面在线。没有接入短信、微信或车载语音。
- 双方都可主动发送，多轮交流，不受原风险沟通记录的一次回复限制。Enter发送，Shift+Enter换行，中文输入法候选确认不会触发发送。单条最多2000字符。
- 发送失败保留草稿，使用同一请求ID重试不重复生成消息。消息保存在本地SQLite，服务重启和重新登录后保留。默认最近100条，支持加载更早记录。
- 对话窗口打开且页面可见、获得焦点时标记已读；不会仅因后台获取联系人就标为已读。发送成功仅代表服务器保存，不代表对方已读。
- 安全员仅可联系当前授权车队的司机；司机只能联系授权安全员，不能读取其他司机会话。全范围安全员可以协助未绑定司机，局部车队安全员需要司机当前绑定核实并属于本队。停用或跨范围重新绑定后，服务端立即重新检查权限。
- 司机端保留“安全停车后交流”提示。此功能不声称能识别真实行驶/停车状态。

实现：`server/messaging.mjs`负责持久化、权限、幂等与已读状态，`server/local-database.mjs`提供私有RPC，`server.mjs`通过现有登录会话鉴权并注入可信身份，`src/messaging.tsx`提供共用窗口与两端入口。

接口：GET `/api/chat/contacts`；GET `/api/chat/messages?peer=用户ID[&before=序号|&after=序号]`；POST `/api/chat/send`（peer/content/client_id）；POST `/api/chat/read`（peer/through）。聊天正文仅存在chat_messages，审计只记对象和长度。客户端不能指定发送者或直接访问聊天表。

测试：Node24运行 `node --test tests/messaging.test.mjs`。覆盖双向发送、未读/已读、跨车队权限、未绑定司机边界、重试及冲突、历史分页、服务重初始化、故障事务回滚与账号权限撤销。浏览器使用本地preview_admin与preview_driver进行了双向验收，测试消息均明确标记为验收消息。

本地服务地址：管理员 `http://127.0.0.1:3100/`、司机 `http://localhost:3100/`，两个主机名分别保存Cookie，方便同时演示两种角色。本次修改前备份：`var/before-messaging-20261029.sqlite`。纯托管环境需要同时部署对应消息服务，不能只替换前端。
