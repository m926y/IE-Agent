# 案卷助手、个人反思与业务聊天

## 使用入口

1. 在风险监控中选择案卷，使用“生成处置建议与个性化培训”。助手读取该案卷的最近15条证据、当前评分、最近15项学习记录，以及当前安全员与有效绑定司机之间最近20条会话。展开依据可以核对原文与时间。
2. 生成内容是课程草稿清单。管理员确认入库后，还需在课程中心审核，再按原有 C/D 级、可信度及停车条件分配。不会自动认定司机违规或关闭案卷。
3. 选中案卷后，也可向平台 Agent 询问本案建议。新增工具 `get_case_learning_context`、`generate_case_training` 均在服务端重新验权。使用现有外部 Qwen 配置；模型不可用时明确显示规则模板。
4. 司机进入原互动课程，完成选择题并填写个人风险反思，反思80—180字（不计空白）。反思提示汇总本人评分窗口内出现最多的三类报警及原始条数，明确不等同独立违规次数。首次作答保存本次风险依据。错题主题、解析、补学历史继续保留。
5. 新生成的专题课程可在司机培训任务中阅读，回答情境题、填写个人反思和行动计划。安全员可查看结构化原文并人工验收。主观回答不自动编造成测验分数。
6. 消息窗口可选择关联案卷和培训，消息附有跳转按钮。培训分发生成聊天提醒；司机提交线上培训生成完成消息，优先通知分配人，分配人不可用时通知授权车队内安全员。重复请求不重复发送。

## 数据与边界

- `chat_business_refs` 保存消息与案卷、任务的结构化关联，启动时自动创建。关联对象与当前司机绑定、车队权限重新校验。
- 聊天消息已有 `read_at`，界面明确显示“未读/已读”。只有会话打开、页面可见且聚焦、消息列表位于底部时才发已读回执。通知已读不等于业务任务完成。
- 互动课程的 `learning_record` 增加 `personal_question`、`reflection`；已完成旧记录保持原样。非互动课程使用 `personal_course` 结构保存情境回答、反思、行动计划与补学记录。退回后补学保留历史。
- 保存学习记录与自动消息是两个可重试步骤；消息失败时可以重复提交修复，不重复计分。案卷/批量分发内的任务、通知与聊天在同一数据库事务中保存。
- 案卷来源仍为真实历史数据回放，评分日期与事件日期分别展示；聊天陈述未经独立核实，测验通过不能代替真实风险复查。没有向真实车载终端下发。
- 现有课程审核、账号绑定、C/D培训限制、低可信度核验及人工验收保持生效。

## 主要实现

- `server/personal-learning.mjs`：授权上下文、分发/提交聊天联动。
- `server/messaging.mjs`：业务关联校验与已读回执。
- `server.mjs`：Agent工具、生成接口、反思与主观题提交校验。
- `src/case-learning.tsx`、`src/personal-lesson.tsx`、`src/training.tsx`、`src/messaging.tsx`：使用界面。
- `tests/personal-learning.test.mjs`、`tests/training-quiz.test.mjs`、`tests/risk-monitor-api.test.mjs`：权限、幂等、反思字数与完整HTTP消息回执流程。
