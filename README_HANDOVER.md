# AI 安全员交接班助手

入口：数据总览 → AI 交接班（`#/handover`）。管理员和安全员可使用，司机和队长不可访问。现有账号、案卷、培训和评分记录保持原样。

## 每日使用

默认每天北京时间18:00下班，自动生成一份本人交接单。在“我的交接设置”修改下班时间、是否自动生成、默认接班人和是否使用千问。未设置接班人也会生成并通知本人，之后可选择接班人发送交接。接班人收到通知和待办，明确点击确认接收；接收不改变案卷、培训和回访的实际状态。双方可追加说明，原始快照和总结不被覆盖。支持下载Markdown。

下班前可点击“预览当前交接”查看截至此刻的临时总结，明确标注未归档，不占用当日正式交接单。预览不能指定接班、确认或补充。正式生成以保存的下班时间为准。

Agent新增 `get_shift_handover` 与 `generate_shift_handover`，可说“查看我的交接单”“生成今天的交接总结”。未到下班时间不允许生成；重复操作返回同一份。

## 统计和权限

- 当日范围是北京时间00:00至配置的下班时间，记录新增/关闭案卷、培训提交/验收、本人收发消息和操作次数。风险与培训统计覆盖该安全员授权车队，个人聊天及操作只统计本人。
- 未闭环案卷、待验收/逾期/未完成培训、未回复司机会话、评分异议和回访使用**生成时实际状态**。历史回放单独标识；评分参考显示实际评分日期。
- 交接单可由交班人、指定接班人及覆盖该车队的管理员访问。接班人的车队范围必须覆盖整个交接单；角色、停用及范围变化实时重验。模型、通知与下载不绕过权限。
- 用户已明确授权此功能把车辆编号、账号和相关聊天原文发送给已配置千问生成总结。仅发送业务字段，不发送密码、令牌、头像或认证记录。模型最多读取120项重点待办、当日最近80条相关聊天，完整未完成清单仍留存在数据库和页面中；司机陈述须注明待核实。模型建议引用真实事项ID，无法匹配的输出拒绝使用。

## 自动生成和补生成

调度器运行于 `scripts/start-local.mjs` 启动的本地持久数据库服务，每分钟检查，不依赖网页打开或安全员保持登录。账号首次启用当日开始，不补造启用前交接单。数据库以“交班人+日期”唯一约束保证幂等；每轮最多补8份，停机多日会分批追补。生成、通知和审计同事务保存。未完成事项快照是补生成时当前状态，**不能还原停机期间下班瞬间的完整业务状态**，交接单显式保留截止时点和实际生成时点。

千问调用异步运行，模型失败不丢交接单：先保存本地事实总结，最多3次尝试、间隔5分钟重试；重启可以恢复未完成调用。页面每15秒刷新。模型只生成总结和建议，不修改业务状态。当前调度需要后台服务持续运行；电脑关机/服务关闭时无法准时执行，恢复后补生成。纯静态前端或单独启动 `server.mjs` 不含此调度服务。

交接单的数量概况始终由程序直接拼接，避免模型重复统计时误计数量；千问负责有依据的优先事项和具体跟进建议。发送模型前将ISO时间转换为北京时间，并附业务状态说明。待回复会话是末条消息来自司机的候选，并不表示每条确认消息都必须回复。

表：`handover_settings`、`handover_reports`、`handover_notes`，启动时自动建立，不开放通用REST写入。公共接口：GET `/api/handover/data`、`/view?id=...`；POST `/settings`、`/generate`、`/assign`、`/accept`、`/note`，服务端注入当前操作者。

验证：`node --test tests/handover.test.mjs tests/action-center.test.mjs tests/messaging.test.mjs tests/full-data.test.mjs`。备份：`var/before-handover-20261031.sqlite`。
